# Search UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the "Search this area" button into the sidebar with a staleness hint, and add a dashed viewport rectangle overlay on the map so the user can see exactly what area will be searched.

**Architecture:** `CampMap.svelte` owns the Leaflet rectangle layer and shows/hides it by watching the existing `searchPending` store. `FilterSidebar.svelte` receives an `onSearch` callback prop and reads `searchPending` to render the hint + button. `+page.svelte` wires the two together and drops the old floating overlay.

**Tech Stack:** SvelteKit, Svelte 5 runes, Leaflet (already imported in `CampMap.svelte`)

### Task 4: Add viewport bounding box overlay to the map

**Files:**
- Modify: `frontend/src/lib/map/CampMap.svelte`

- [ ] **Step 1: Add a `boundsRect` variable and the overlay logic**

In the `<script>` block of `CampMap.svelte`, add a `boundsRect` variable after the existing `let pinsLayer` line:

```ts
let boundsRect: any = $state(null)
```

- [ ] **Step 2: Add a top-level `$effect` that reacts to `searchPending`**

In Svelte 5, `$effect` must be declared at the top level of `<script>`, not inside callbacks. Because `map` and `L` are `$state`, the effect re-runs automatically when they are set by `onMount`. Add this block after the existing `let` declarations (before `onMount`):

```ts
$effect(() => {
  if (!map || !L) return
  if ($searchPending) {
    const bounds = map.getBounds()
    if (boundsRect) {
      boundsRect.setBounds(bounds)
    } else {
      boundsRect = L.rectangle(bounds, {
        color: '#2563eb',
        weight: 2,
        dashArray: '6 4',
        fillColor: '#2563eb',
        fillOpacity: 0.06,
        interactive: false,
      }).addTo(map)
    }
  } else {
    if (boundsRect) {
      boundsRect.remove()
      boundsRect = null
    }
  }
})
```

- [ ] **Step 3: Update the rectangle bounds on subsequent `moveend` events**

When the user pans again *while* the rectangle is already visible (`searchPending` was already `true`), the `$effect` won't re-run because `searchPending` didn't change. The rectangle's bounds need to update on every pan. Extend the existing `map.on('moveend', ...)` inside the `onMount` IIFE:

```ts
map.on('moveend', () => {
  searchPending.set(true)
  if (boundsRect) boundsRect.setBounds(map.getBounds())
})
```

- [ ] **Step 4: Verify the rectangle behavior**

In the browser:
1. Pan the map — a dashed blue rectangle appears outlining the viewport.
2. Pan again — the rectangle updates to the new viewport.
3. Click "Search this area" — the rectangle disappears.
4. Pan again — the rectangle reappears.

```bash

git commit -m "feat: show dashed viewport bbox overlay when search is pending"
```
